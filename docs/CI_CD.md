# CI/CD pipeline

`.github/workflows/ci.yml` runs on pull requests and pushes to `MANUS`, with a manual `workflow_dispatch` option. The workflow has four gates.

The `backend` matrix installs the declared `vector`, `test` and `agentic` extras on Python 3.10, 3.11 and 3.12, then runs the local package unittest suite and bytecode compilation. The `frontend` job installs the frozen pnpm workspace, runs unit and route-manifest tests, strict TypeScript checking, Playwright axe and E2E checks (installing Chromium), and a Vite production build. The `contracts` job installs `jsonschema==4.23.0`, validates the root legacy schema/example and the frontend demo-view schema/fixture, then runs seven positive/negative frontend contract tests. These are repository-local schemas, not an approved OpenAPI contract or public API DTO. No excluded database, vector index, or derived source extract is required by these jobs.

When a push to `MANUS` passes all gates, the `package` job uploads `frontend/dist` as a short-lived GitHub Actions artifact. Separately, `.github/workflows/deploy-cloudflare.yml` triggers on pushes to `MANUS` and builds/deploys `frontend/dist` if the Cloudflare Actions secrets are available; if credentials are absent, only its deploy step is skipped. This workflow is independent of `ci.yml`: it has no dependency on CI success and no human-approval environment gate, so a push may publish even while tests fail or are still running. This task did not push, run that workflow, inspect secret values, or verify a production deployment. Review the security/identity/ACL gates and obtain approval before enabling or relying on a production publication path.
